Module 1

Le Modèle Séquentiel

Parfaitement Adapté à l'Industrie

Production d'une Voiture

Conception → Assemblage → Peinture → Contrôle → Livraison
  • Processus linéaire et séquentiel
  • Chaque étape doit être parfaite
  • Pas de retour en arrière possible

Pourquoi ça Marche ?

🚗 → ❌ Modification

  • Contrainte physique : produit non modifiable
  • Rappel de véhicules = extrêmement coûteux
  • Mieux vaut tout vérifier avant

Module 2

L'Adaptation au Logiciel

Le Waterfall et le Cycle en V

Le Modèle Waterfall

Analyse & Conception
        ↓
   Développement
        ↓
      Tests
        ↓
   Déploiement

Inspiration directe de l'industrie

L'Avantage du Logiciel

💻 → ✅ Modification

  • Application modifiable après production
  • Coût relativement faible
  • Déploiement d'une nouvelle version
  • Mais on a gardé le modèle séquentiel !

Les 3 Problèmes du Waterfall

  1. Passages de relais : silos, malentendus, délais
  2. Effet tunnel : 6 mois sans retour
  3. Dette technique : peur de refactorer

Module 4

La Solution

L'Intégration Continue et l'Agilité

Deux Pratiques Indissociables

Agilité

  • Petites étapes
  • Sprints courts
  • Produit viable

CI

  • Intégrations fréquentes
  • Tests automatisés
  • Feedback rapide

L'une ne peut exister sans l'autre

4 Pratiques Clés de la CI

  1. Intégration fréquente : quotidienne (ou plus)
  2. Automatisation du build : zéro erreur humaine
  3. Code auto-testé : tests = confiance
  4. Correction immédiate : 🔴 → priorité #1

Le Workflow CI

Dev → Commit → Build → Tests → ✅ / 🔴
                                  ↓
                              Correction
                              immédiate

Les Bénéfices

  • ✅ Réduction des risques
  • 🔄 Refactoring sans crainte
  • 📝 CI as Code (GitLab CI/CD)
  • ⚡ Feedback en minutes (pas en semaines)

CI as Code


# .gitlab-ci.yml
stages:
  - build
  - test
  - deploy

build:
  script:
    - npm install
    - npm run build

Pipeline versionné avec le code

Module 5

De la CI au CD

Le Déploiement Continu

CD = CI + Déploiement Auto

Commit → Build → Tests → Deploy
         ✅      ✅       🚀

Pourquoi s'arrêter à l'intégration ?

Deux Révolutions Technologiques

  1. Kubernetes : Orchestration de conteneurs
  2. Infrastructure as Code : Terraform, Ansible

Avant : déploiement complexe, manuel, fragile
Après : kubectl apply

Le Pipeline de Déploiement

1. Commit Build (tests unitaires < 10 min)
           ↓
2. Tests avancés (fonctionnels, perf, sécu)
           ↓
3. Déploiement automatique en prod

Les 4 Fondations du CI/CD

  1. Infrastructure as Code : Terraform
  2. Containerisation : Docker
  3. Orchestration : Kubernetes
  4. Culture DevOps : collaboration
